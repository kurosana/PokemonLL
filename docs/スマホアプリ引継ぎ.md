# スマホアプリ引継ぎ

個体値研究とバトルシミュレーションを、ネイティブのスマホアプリに移すときの要約。作者が Web 版を直す過程で特に気にしていた **使いやすさの考え方** と、**このチャットまでに固めた機能の姿** を残す。

これは実装手順書ではない。画面の細部・日付付きの指摘の全文は `docs/サイトUI改善.md` にある。計算の正しさは `docs/対戦仕様.md` と `src/lib/pogo/` を正とする。余白やタップサイズの一般論は `docs/ui-readability.md` を参照する。

---

## この文書で伝えたいこと

1. **スマホで読む順番を崩さない。** 広い画面用に横へ引き伸ばすより、狭い画面で一度読み切れる並びを守る。
2. **見た目の洗練より、飲み込みやすさと押しやすさが先。** おしゃれさは、そのあとで足す。
3. **隠れた操作は小さく知らせる。** 本体の数字や表を押しのけない。
4. **ポップアップは「いま何をしているか」が一目で分かる形にする。** 保存ボタンで区切るより、入れた瞬間に反映する場面では、反映を優先する（初期条件など）。
5. **数字入力は「書き換え」として扱う。** 既存の桁の左にカーソルが立って、削除キーを何度も押す必要がないようにする。

Web 版は React + Vite のブラウザアプリ。アプリ化するときも、**同じ計算・同じ並び・同じ操作の意味** を保つことを優先する。見た目だけ iOS/Android の定番に寄せて、情報の優先順位を入れ替えない。

### このプロジェクト全体の前提（個体値・シミュ共通）

- **スマホでの利用が正。** 横長画面は、スマホの読み順を崩して引き伸ばさない。必要なら 2 カラムなど「見やすさだけ」を足す（詳細は `docs/サイトUI改善.md` の広い画面の節）。
- **縦の無駄を減らし、適度な余白は残す。** 中央揃え・左揃えで、数字や塊の境が一目で分かるようにする。
- **ポケモン選択・検索** は [くろさなつーる](https://kurosana.github.io/ku6-3naTool/) のパーティシート／検索に近い操作感を目標にした（履歴ドット、ひらがな・カタカナ・ローマ字、名前が完全一致して候補が1種類だけのときはタップなしで確定、など）。
- **タブ** はアクロママシーン9637号の区外／区内の切り替えを参考に、**個体を入れたあと** に見方を変える位置に置く。
- **SCP** はみんポケ系（Web の `formatScp` / statProduct）。アプリ移植時は Web と同値になるようテストする（例: マリルリ 1 位 SCP ≈ 1818 — 作者が渡した検算値を参照）。

## 作者の使いやすさの理念（横断）

### 優先順位

| 先に満たすこと | 後回しにしてよいこと |
| --- | --- |
| 1画面で何をする場所か分かる | 背景の装飾 |
| 主操作が1つに見える | 細かいアニメーション |
| タップ・なぞりの当たり判定 | 列を詰めて1画面に全部入れる |
| 先に知りたい数字が大きい | すべて同じ字号 |
| 端に貼り付かない余白 | 画面幅いっぱいまで要素を広げる |

### スマホと広い画面

- **基本の並びはスマホ用。** タブ、個体値、結果、表の順は、スマホで自然に読める順を正とする。
- **横幅が余っても、同じ並びを横に伸ばさない。** 情報が増えない部分は中央に置き、左右を余白にする。表だけは読みやすい幅で止め、必要なら横スクロールより **行を高く・列間を空ける**。
- **720px 前後を境に、個体値バーだけレイアウトを変える**（ラベルを上、バーを下）。これは「小さい画面の専用ルール」であり、タブレットで無理に PC 版に戻さない。

### 言葉と記号

- 画面上は **「ポケモン」**（`pkmn` などの略称は使わない）。
- 順位は **`1位`**（`#1` は使わない）。
- リーグは **`Image/league` の紋章**で見分ける。同じ意味のリーグ名を文字でも並べない（カスタムだけ例外で「カスタム」等）。
- 利用者向けに **実装の説明を残さない**（「個体値と同じ検索です」など）。

### 触り方

- **個体値バー:** 左右にはっきり動かしたときだけ値が変わる。上下スクロールを優先する。操作が分からないので、バー下に小さく「スライドで入力できます」。
- **表:** 表の中でスクロールが終わったら、ページ全体がスクロールする（表に指を閉じ込めない）。
- **検索ポップアップ:** 一度出したら **上端・左端は動かさない**。中身が小さくなっても、下と右が削れる。キーボードで下が隠れるときは **上に固定**。
- **数値の欄（初期条件など）:** フォーカスした時点で **中身を空にする**。何も入力せずに離れたら **元の値に戻す**。数字を入れたときだけ確定する。これにより、桁の左端にカーソルが立って削除が面倒、という状態を避ける。

### ポップアップの型（作者が「ほぼ完璧」と評価した初期条件）

- 全画面の半透明背面 + **中央の白いパネル**（角丸、セクション間に余白）。
- 見出し → 本体（スクロール可）→ 右下に **閉じる** だけ、という三段。
- トグルは **今の状態を文字で書く**（例: 初期条件 ON / 初期条件 OFF）。「機能」という名前だけでは、入っているかどうか分からない。
- **保存は出さない。** 変更はその場でシミュに反映する。閉じるは「編集を終える」意味だけ。
- 攻撃・防御ランクは **-4～4 の並びボタン**（個体値バーと同系統の、段階が一目で分かる UI）。
- HP は **残量と受けたダメージの二通り** で同じ状態を表す。「または」と小さな注釈で、どちらか一方でよいと伝える。

## 個体値研究（アプリで再現すべき要点）

### 操作の流れ

1. ポケモンを選ぶ（検索はひらがな・カタカナ・ローマ字・英語・図鑑番号）。
2. 個体値を入れる（相棒 → 攻撃・防御・HPのバー。相棒はレベル 51 まで含めるか）。
3. **その下で** 「個体チェック」と「数値研究」を切り替える。

タブを入力より上に置かない。先に個体を決めてから見方を変える。

### 個体値バー

- 各マスに **0～15 の数字** を表示。左に「今選んでいる値」だけを大きく出す方式はやめた。
- **5と6、10と11 の間** は、ほかのマスより隙間を広く（原作の区切りに近い）。色は 0 / 1–5 / 6–10 / 11–14 / 15 で段が分かる。
- 狭い画面: ラベルはバーの上、バーは **ほぼ全幅** だが、**左右は画面端まで詰めない**。端の余白は **5と6のあいだの隙間と同程度**（完全な edge-to-edge は避ける）。
- スライド入力とページスクロールの競合に注意（上記「触り方」）。

### 個体チェック

- リーグは **1行3列の紋章**（リトル・スーパー・ハイパー）。縦3段に積まない。
- セル内の優先度: **順位（最大）→ CP・SCP（中）→ レベル・攻撃・前CP（小）**。
- 順位の色: 1位=金、2–9=赤、10–99=オレンジ。
- **前CP** は、検索したポケモン自身の CP（進化先の行でも、親の姿の CP ではない）。
- ギルガルド・メテノ・ゲンシなど **フォルム違い** は、中身が違えば別行。検索で片方を選んでも、個体チェックには **両フォルム** を出す（ギルガルド・メテノ）。
- メガの表示名は **`リザードン(メガ)`** のように括弧（Web 本番 `main` に合わせた表記）。

### 数値研究

- 要約ブロック: 順位 / CP+SCP / 攻撃・防御・HP・レベル。個体チェックと同じ **文字の大小の考え方**。
- **順位表の列順（確定）:** 順位 → IV → CP → **SCP** → 攻撃 → 防御 → HP → Lv。SCP の計算は Web と同じ（みんポケ式。`formatScp` / statProduct）。
- IV・攻撃・防御・HP は **やや小さく・列幅を抑える** ことで SCP 列を足してもスマホで読める。
- 順位列と IV 列の間だけ **縦線**。ほかはマス目にしない。
- 絞り込みは表の手前で畳む。いつも見せるのは SCP順位のプルダウン程度。
- いまの個体の行は、表内に見えているあいだは固定しない。**通り過ぎた方向だけ** にピン留め。

### データ・計算

- 種族値・進化・メガ・ゲンシ等は `public/data/` と `evolutionLine.ts` 周り。アプリでも **同じ JSON と同じグルーピング** を使う想定。
- 詳細な UI 文言・日付付きの変更履歴は `docs/サイトUI改善.md` の 2026-10-29 節以降を参照。

## バトルシミュレーション（アプリで再現すべき要点）

### 画面構成の考え方

- **自分と相手を横並び**（スマホでも2列。詰まりすぎる場合は gap を詰めるが、**縦に積み替えない** のが Web の方針）。
- カード内: 選ぶ → CP/SCP → 実数値 → 個体値（ポップアップ）→ 技 → **初期条件**（カード最下部）。
- タイムライン・対面表・シールド9マスは **カードの外**。シールド枚数は表で選び、タイムラインにシールドマスは置かない。

### 個体値（シミュ）

- カード上は **3つの数字ボタン** のみ。タップで **中央ポップアップ**（検索は上から、個体値は中央）。
- ポップアップ内: 画像、CP/SCP、実数値、Lv50/Lv51、SCP1位・2桁A/B/H最大、バー、OK/閉じる。バー変更は **OK まで確定しない**（初期条件とは対照的）。

### 初期条件（このチャットで完成形に近づけた機能）

**目的:** 0ターン目から「途中の対戦」を再現する（HP・ゲージ・能力ランク）。

| 項目 | 仕様 |
| --- | --- |
| スコープ | 自分と相手 **独立**。ON にした側だけ 0ターン目に反映 |
| HP | 残量 ⇔ 受けたダメージ。どちらか入力で連動。整数、0～最大HP |
| ゲージ | 0～100 整数。ノーマル1回分の ± ボタン（技名付き）。範囲外・小数は入れない |
| ランク | 攻撃・防御それぞれ -4～4 |
| 反映 | **入力即反映**。保存画面なし |
| UI | タイムラインカスタムと同系統の **幅いっぱいボタン** で開く。ポップアップは初期条件型（上記） |
| トグル | **初期条件 ON / OFF** と表示 |
| 数字欄 | フォーカスで空、未入力で離脱なら元に戻す |

計算ルール全文: `docs/対戦仕様.md` の「初期条件」。

### タイムラインカスタム

- 表の下の **大きなボタン** で開く。編集中は黄色い枠などで ON が分かる。
- 1ターン技（サイコウェーブ等の **1T スペシャル含む**）は、狭い画面で **はみ出さない**。技名はパネル幅に応じて縮小、×ボタンも小さく。必要ならセル内でフォントをさらに詰める。
- ×は技セル内（自分=左、相手=右）。2ターン以上は名前と×を2行に。
- 手順が尽きたあとは **最適で続行**。再開時は最適の続きを手順にマージ（Web 実装済み）。

### タイムライン表示・操作（カスタム以外）

- 残りHPは **変わった行だけ** 表示。
- CCT・シールド・スペシャルボタン等の細則は `docs/サイトUI改善.md` のシミュ関連セクション。

### 計算

- 対戦エンジンは `src/lib/pogo/simulate.ts`。タイムライン手順は `timelinePlan.ts`。
- **初期条件** は `FighterInput` の startHp / startEnergy / startAttackStage / startDefenseStage（Web 実装済み）。
- 仕様変更時は **対戦仕様.md を先に更新** する文化。

## Web 版との関係（アプリ開発時）

- **データ:** `public/data/`（stats, evolutions, pvp_bundle, cp_multiplier 等）をアプリに同梱または同 API で取得。
- **計算ロジック:** TypeScript をそのまま共有（React Native / Capacitor / KMP 経由など）するか、仕様書に沿って移植。SCP・ダメージ・タイムラインは **Web と結果一致** をテストする。
- **UI 詳細:** 日付・意図付きの一覧は **`docs/サイトUI改善.md` のみ** メンテする。本ファイルは「アプリ引継ぎ用の要約」として、大きな方針変更時に更新する。
- **本番 Web:** Fork 先で PR をマージしたあと、上流 `tsutayuki/PokemonLL` の `main` 向け compare で反映、という流れ（作者の運用）。アプリのストア配信とは別。
